## Reading it

- **Floors** (exact-title / exact-content / substring / code / typo) are
  asserted at 1.0 in CI — lexical search has no excuse to miss an exact,
  mid-word, or fat-fingered term.
- **paraphrase = 0.00 is expected and is the point.** "protect against stolen
  access tokens" shares no lexical tokens with the "Session auth vs JWT" chat;
  only semantic retrieval (phase 3) closes this. The paraphrase row is the
  honest measuring stick for the embedding lift, not a bug.
- **ru = 0.50 and es = 0.33 are the honest, previously-hidden numbers.** The
  original ru/es queries reused the fixtures' exact surface word forms and
  scored 1.0, which measured nothing about stemming. This row now also
  includes queries built from genuinely different inflections than what's in
  the fixture text — Russian case changes ("поездку"/"Испанию" accusative vs.
  the fixture's genitive/prepositional forms; "Мадрида"/"Барселону" vs. the
  fixture's nominative/genitive) and Spanish conjugation/agreement changes
  ("preparó" 3rd-person preterite vs. the fixture's "preparo" 1st-person
  present; plural "arroces"/"azafranes"/masculine "auténticos" vs. the
  fixture's singular/feminine forms). `to_tsvector('simple', …)` does no
  stemming, so a different case or conjugation is frequently a different,
  unmatched token — some of these return zero results outright. This is what
  phase 3 (embeddings) is expected to close, not a regression to fix here.
- **oversized = 1.00 confirms today's baseline behavior, not a floor.** The
  corpus previously had no fixture larger than `CHUNK_MAX_CHARS` (3000,
  `conversation-chunker.ts`). The added fixture's single message is ~3.6x
  that budget; `chunkByCharBudget` passes an over-budget item through as its
  own unsplit chunk (no truncation), so the whole message — including content
  near its tail — is indexed and currently fully retrievable lexically. This
  row is expected to move once the chunker-fit layer (#517) changes how an
  oversized message is chunked; every pre-existing fixture's row is not.
