Run a shell command as the target Machine's OS user via `zsh -f -c`.

<instruction>
`command`: shell text, required; `cwd`: a literal existing directory; a `cwd` that carries any scheme other than `machine://` is refused as `invalid_path` while a Workspace is entered; an omitted `cwd` uses the Workspace root while one is entered and the default directory of the current Machine otherwise; a relative `cwd` resolves from the Workspace root without confinement (`..` may leave it), or from the default directory of the current Machine with no Workspace; no `~`/`$` expansion; `env`: variables added to the fixed managed base, whose keys cannot be replaced; no shell state persists between calls. The shell is Zsh: write Zsh syntax, not Bash syntax. `-f` means no startup file is read, so `~/.zshrc` and `~/.zshenv` do not run and no alias, function, or option they set is available. Output returns as produced, cut at the operator-configured byte bound per stream on this host; a timeout with a proven stop reports `timed_out` plus partial output. A `machine://<name><absolute path>` `cwd` runs the command on that Machine there, with the same managed base and input, time, and process bounds but the Machine's own 32,000-unit stream bound; while the Workspace is on a Machine, an omitted or relative `cwd` resolves on it and a bare absolute `cwd` is that Machine's path. Set the directory of a command with `cwd`, not with a `cd` in `command`: in an entered Workspace give no `cwd` or one relative to its root, and with no Workspace give an absolute `cwd`. An `ssh://` working directory is refused: only `bash` runs through an `ssh://` locator.
`async: true` starts the command as a background job and returns its `job://` locator immediately, but only when the command runs on this worker's own Machine. `unlimited: true` removes a job's lifetime only when the operator permits it; the model cannot choose a duration or change an operator bound. A working directory on another Machine, including a Machine Workspace default, refuses both fields with "`async` is unavailable for Machine `<name>` on this attempt. Run the command synchronously."
This tool runs only on a Machine whose daemon reports the `zsh` capability. When it does not, the call fails and names the shell to use instead.
</instruction>

<output>
- A result is plain text, not JSON: one status header `exit <code>`, continued with `, <seconds> s` (one decimal) when the producer measured the command's wall time, then stdout verbatim, then a `[stderr]` line and the stderr when it is non-empty; `(no output)` when both streams are empty.
- A stream that does not fit inline shows its first lines, one `[lines <a>-<b> omitted; …]` line, and its last lines. When the Run can read artifacts, the Machine's captured stream is stored as `artifact://bash-<n>/stdout` or `artifact://bash-<n>/stderr` (marked incomplete when the byte bound cut it), the omitted line names the `read` range that holds the captured rest, and `[full result: …]` ends the text; otherwise it says `full result not stored`. The tool's result cap never shortens this text again.
- `[output cut at the bound]` marks output a stream bound cut, before the artifact notice; a stream that only the inline preview shortened carries no marker.
- A failed command's `command_failed` result carries this same text in its message, with the non-zero exit code; a `timed_out` message starts with `timed out` and names the measured elapsed time in seconds, and names no exit code because the command never exited.
- A backgrounded result has no exit header: it says the command continues as a job. You get a notice when it settles. Do not poll it.{{#if tools.wait}} Use `wait` to wait for job settlement.{{/if}}{{#if tools.stop}} Use `stop` to end a job.{{/if}}
- Text is neutralized for reserved delimiters: a tag-shaped token naming `system-reminder`, `tool-call`, `tool-result`, `user_chat_history`, `user_personalization`, `skill`, or `available_skills` is angle-escaped (`&lt;tool-result&gt;`); every other character is the output as produced, `</div>` included.
</output>

<critical>
Alpha Machine authority, not tenant isolation. A Machine command runs as that Machine's OS user with no sandbox: its registered roots bound addressing only and can be changed by that user, and a Machine shared between users gives no isolation between them. Every llame user whose permissions allow it has the same authority on that Machine.
