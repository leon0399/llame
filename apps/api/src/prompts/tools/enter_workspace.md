Enter a Workspace: a directory on the current Machine, or on a configured Machine named by a `machine://` locator. With `worktree`, create a git worktree of the clone you name and enter that.

<instruction>
`path`: required. Either an absolute directory path on the current Machine, or a `machine://<name><absolute path>` locator naming a directory inside one of that Machine's registered roots (list Machines with `read machine://` and a Machine's roots with `read machine://<name>`). The current Machine is the entered Workspace's Machine, or the default Machine when no Workspace is entered. The path is checked by the operator's `enter_workspace` permission group before it is probed and checked again after canonicalization. Relative paths and paths containing NUL bytes are invalid. The canonical root becomes the working root for relative file paths and Bash `cwd` values beginning with the next model step; relative paths and bare absolute paths address the bound Machine, and `bash` runs there. `..` may leave the root and Workspace entry does not confine Machine operations. The result lists bounded, proactively eligible skills discovered beneath the Workspace's `.claude/skills`, `.agents/skills`, and `.llame/skills` sources; read their instructions with `skill://<name>` on the next model step.

`worktree`: optional. Present, `path` names a source clone and the call creates a git worktree of it, then binds that directory. Pass `worktree: {}` for a generated name, or `worktree: {"name": "…"}`. `worktree.name` must not start with `-` or contain a `.` or `..` segment; the branch is `llame/<name>`, or the name itself when it holds a `/`. `worktree.baseRef` chooses the commit the branch starts at and must not start with `-`; an omitted value uses the source HEAD and no fetch runs. The directory is `<parent>/.llame-worktrees/<repository name>/<slug>` beside the clone, or under the clone's `worktree_base`, and never inside the clone. The operator decides the submitted path, its canonical form, the main clone git reports, and the new directory, so a refused one creates nothing. Each call creates a new worktree: it never re-enters the clone. If the source checkout has a `.worktreeinclude` file, creation also copies the ignored files it selects, such as `.env`, once into the new worktree. A selected symlink fails creation, so select files, not package trees like `node_modules/`.
</instruction>

After an entry that binds or switches the root, the next step carries the repository's git state as a context item after the tool result; the result itself holds none.

<critical>
Workspace selects a working root but is not filesystem confinement; operations keep the Machine user's authority, and entering a Workspace can start processes on that Machine. Operations run as that Machine's OS user with no sandbox: its registered roots bound addressing only and can be changed by that user, and a Machine shared between users gives no isolation between them.
</critical>
