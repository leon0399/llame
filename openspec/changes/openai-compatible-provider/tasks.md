# Tasks

Delivery stack: `master <- openai-compatible-provider/proposal <- openai-compatible-provider/types <- openai-compatible-provider/reasoning-parts <- openai-compatible-provider/reasoning-metadata <- openai-compatible-provider/finalize`.

The proposal branch owns this ledger, the proposal, the design, and the
delta specs; its review and approval follow CONTRIBUTING §3 and are not
tasks here. The types layer owns the wire-named provider types and closes
issue #339. The reasoning-parts layer owns part identity, render/export glue
repair, panel grouping, and the cap deletion. The reasoning-metadata layer
owns the durable provider-metadata channel, its Responses producer, and its
replay, and closes #883. The finalize layer owns canonical spec
synchronization and archive movement only, and closes no issue.

Use `$gh-stack` for every stack operation and `$openspec-apply-change` for
implementation. Create the types layer only after explicit proposal-PR
approval; publication and merge each require their own authorization. The
sibling `anthropic-provider` change (PR #885) merges after this one and
rebases its `instance-config` delta onto this change's merged wording and
type names.
