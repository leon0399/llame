## Delivery stack

Use `$gh-stack` for every branch operation and `$openspec-apply-change` for
each implementation layer, after proposal approval only. The experimental
PRs #1584, #1588, and #1590 stay open and follow their branches: each branch
is renamed on GitHub to its layer name, the layer is rebuilt from its parent
by importing the experiment's files as one commit, and the renamed remote
branch is force-pushed. The experiment's client branch is split into
`config`, `client`, and `service` so that no layer exceeds the budget.

```text
master
  <- decision-rerank/proposal
  <- decision-rerank/config
  <- decision-rerank/client
  <- decision-rerank/service
  <- decision-rerank/engine
  <- decision-rerank/web-search
  <- decision-rerank/grep
  <- decision-rerank/ui
  <- decision-rerank/finalize
```

| Layer        | Parent       | Ownership                                                                                                                                | Authored estimate | Closes       |
| ------------ | ------------ | ---------------------------------------------------------------------------------------------------------------------------------------- | ----------------- | ------------ |
| `proposal`   | `master`     | Proposal, design, deltas, this list, and the issue amendments.                                                                           | ~2,000            | none         |
| `config`     | `proposal`   | `system-one` provider type, headers, `decisionModels[]`, `webSearch.rerank` and `tools.grep.rerank` (`{ model }`), boot checks, example. | ~900              | none         |
| `client`     | `config`     | The decision protocol and client (one request, retries, bounds, parsing) with their tests.                                               | ~1,250            | none         |
| `service`    | `client`     | The service (card requests, chunking, merge, log line), module, `ToolContext.decisions`, worker wiring, operator doc, CHANGELOG.         | ~1,250            | none         |
| `engine`     | `service`    | `apps/api/src/ranking/`, fixtures, `ranking:eval`, `ranking:record`, docs.                                                               | ~800              | none         |
| `web-search` | `engine`     | Dedupe, the rerank stage, the fits-inline guard, the note, `display.rerank`, docs.                                                       | ~1,000            | #1433, #1435 |
| `grep`       | `web-search` | `objective`, whole-run ranking, the guard, the reserve, `ranking: "unavailable"`, `display.rerank`, the prompt, docs.                    | ~1,100            | #1521        |
| `ui`         | `grep`       | `display.rerank` badge and per-row scores in the grep and web search parts, `objective` in the grep parameters, stories, CHANGELOG.      | ~500              | none         |
| `finalize`   | `ui`         | Spec synchronization, task records, archive movement.                                                                                    | ~1,500            | none         |

Estimates are authored lines against the immediate parent (tests, docs, and
specs included); the experiment measured 2,210 lines under
`apps/api/src/decisions/` at its tip, split roughly in half between `client`
and `service`. Generated output, reported separately: the recorded decision
answers under `apps/api/fixtures/ranking/answers/`, regenerated by
`pnpm --filter api ranking:record`.
